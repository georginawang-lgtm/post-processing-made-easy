Train workflow — ROI processing. Use this tab when post-processing scans where testplan.scan_mode = train. Output goes to /mnt/ppo-data-services/post-processing/roi/. Each step below maps to one spreadsheet column on the Date Page.

Recommended run order: pproc (DATA PREP) → revt (VIS REV) → vis QC (VIS EXTRACT-PNG) → revt --spec (SPEC REV) → spec QC (SPEC EXTRACT-PNG) → awscp (UPLOAD — covers both VIS UPLOAD and SPEC UPLOAD).

Note: ROI review does not require --make_extracts. Reject criteria differ from annotations — see the VIS / SPEC EXTRACT-PNG steps (belt, clearance, FO of interest).
1. Launch AWS Instance Train · ROI

Double-click the launcher icon, or run the launcher script from the command line. To reconnect to an existing instance, just run the launcher again. To terminate, go to the launcher window, press q to quit and then 1 to confirm.

⚠️ ALWAYS TERMINATE YOUR INSTANCE AT THE END OF EVERY DAY. Idle AWS instances cost money. When terminating, all data on the computer is deleted unless it is in an S3 bucket (/mnt/<bucket_name>) or your persistent volume (~/volume/<volume_name>).
ℹ️ First-time setup only: follow the AWS Setup Instructions doc before running the launcher for the first time.
launcher
Downloads\ds-ec2-launcher.cmd
2. Connect via MobaX Train · ROI

Open MobaXterm and connect to localhost port 5902 with password ppoadmin. Once connected, open a new terminal in the VNC.

⚠️ Before running any tool, type aa;caf in the terminal. If you see No module named 'cv2' or similar import errors, you forgot this step. The prompt should change to show (full) after running it.
connect to instance
localhost:5902 password: ppoadmin
activate environment
aa;caf
3. Pre-flight — verify file count Optional · Sanity Check

Confirm the number of raw train files matches the spreadsheet before prepping. Same idea as the t3st pre-flight, just with scan_mode train.

⚠️ If the count is 0: check material spelling, asterisks, and the directory. If files are still named frame* instead of train*, renaming hasn't completed yet — software needs more time.
ℹ️ Never cd into an S3 bucket — it causes a major slowdown for every command you run. Always pass full paths.
template — count train files
dl ls /mnt/ppo-experimental-data/<PROJECT>/fo/<dm#>_vis/<date>/raw/run* --filter testplan.mat <material> --filter testplan.scan_mode train --bare | wc -l
4. DATA PREP (also DATA PREPer) pproc

Run pproc on the train raw files. The tool detects ROI squares and writes corrected files plus a post_proc_info_<#>.txt manifest under the roi output folder. Run per material, per dm, per date.

ℹ️ Spreadsheet: tick DATA PREP when this finishes; put your name in DATA PREPer. Output: /mnt/ppo-data-services/post-processing/roi/<date>/<vis_camera_serial>/. Use --save_dir to override the destination.
⚠️ Sweeper Path / cal_vis errors mean calibrations are missing or unmounted. Run mount | grep PPO to verify, then mount<#> with password ppoadmin if needed. If calibrations themselves aren't ready, escalate to software (Barrett).
template — pproc train
pproc `dl ls /mnt/ppo-experimental-data/<PROJECT>/fo/<dm#>_vis/<date>/raw/run*/frame*.h5 --filter testplan.mat <material> --filter testplan.scan_mode train -b`
find the manifest filename
ls /mnt/ppo-data-services/post-processing/roi/<date>/<vis_camera_serial>/post_proc_info_*.txt
5. VIS REV (also REVer · VIS IGNORE) revt

Run revt on the manifest from the DATA PREP step to review the vis ROI masks. Page through and flag bad ones.

ROI review controls:

  • Left click on a mask to highlight blue = mark for redo. Click again to remove.
  • Right click to highlight red = mark scan un-usable, do not upload (this populates the VIS IGNORE column).
  • Use Next / Previous or arrow keys to navigate.
  • Press q to save, ! to discard.
⚠️ If the review window won't open (Could not connect to display, qxcbconnection, or silent no-window), it's a tmux issue. Detach with Ctrl+B then D, kill the tmux, re-make it, and try again. Cause is usually the same tmux session open on two machines.
ℹ️ Spreadsheet: tick VIS REV and put your name in REVer (vis side). VIS IGNORE is set automatically by your right-clicks. ROI review does not use --make_extracts.
template — revt vis
revt /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt
6. VIS EXTRACT-PNG (also VIS EXTRACT-PNGer) eog / vexp

Visual QC of the vis ROI PNGs. Separate step from VIS REV — review = clicking through masks, QC = looking at the actual output.

  • eog *.png — quick browse through all PNGs.
  • vexp <file>.h5 — opens the .h5 directly when the PNG mask overlay obscures detail.
⚠️ Reject any ROI that contains: belt, other FOs that are not the FO of interest, or has too much clearance between the ROI box (yellow) and the ROI square (green) — that's data loss. For density ROIs, meat background is OK as long as FO density is uniform. Don't forget the --ac tag for spec annotations where required.
ℹ️ Spreadsheet: tick VIS EXTRACT-PNG; name in VIS EXTRACT-PNGer. To fix: go back to VIS REV, mark the scan blue, and use vroi (Train Redo) to re-ROI.
browse PNGs (vis camera)
eog /mnt/ppo-data-services/post-processing/roi/<date>/<vis_camera_serial>/*.png
open one .h5 in vexp
vexp /mnt/ppo-data-services/post-processing/roi/<date>/<vis_camera_serial>/<file>.h5
7. SPEC REV (also REVer · SPEC IGNORE) revt --spec

Re-run revt with --spec to sanity-check the spec ROI masks. Same controls as VIS REV.

ℹ️ Spreadsheet: tick SPEC REV; name in REVer (spec side). Right-clicks here populate SPEC IGNORE. Run AFTER VIS REV.
template — revt --spec
revt /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt --spec
8. SPEC EXTRACT-PNG (also SPEC EXTRACT-PNGer) eog / hexp

Same QC as VIS EXTRACT-PNG, but for spec ROIs. Note the path uses the spec camera serial. Use hexp instead of vexp for the .h5 files.

⚠️ Same reject criteria as VIS EXTRACT-PNG: no belt, no other (non-target) FOs, sufficient clearance between ROI box and square. To fix, mark blue in SPEC REV and re-ROI via Redo.
ℹ️ Spreadsheet: tick SPEC EXTRACT-PNG; name in SPEC EXTRACT-PNGer.
browse PNGs (spec camera)
eog /mnt/ppo-data-services/post-processing/roi/<date>/<spec_camera_serial>/*.png
open one .h5 in hexp
hexp /mnt/ppo-data-services/post-processing/roi/<date>/<spec_camera_serial>/<file>.h5
9. UPLOAD (VIS UPLOAD + SPEC UPLOAD; UPLOADer) awscp

Run awscp on the manifest. One run uploads BOTH vis and spec — the VIS UPLOAD and SPEC UPLOAD checkboxes are for independent verification of each side, not because you upload twice.

ℹ️ Spreadsheet: tick VIS UPLOAD after the vis count check, and SPEC UPLOAD after the spec count check. Put your name in the UPLOADer dropdown for each side.
⚠️ No Such File or Directory on upload means the .txt is looking for .h5s that have been moved or already uploaded. If just spec is missing, recovery is possible (Common PP Errors → Advanced Solutions). If vis is missing, re-prep is required.
⚠️ Permissions error? Server is mounted read-only. Run mount<#>w <username> (needs rw permission). If you don't have it, ask Alan Rooks.
awscp — uploads vis + spec together
awscp /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt
verify VIS count (for VIS UPLOAD)
ls /mnt/ppo-post-proc/<PROJECT>/fo/<dm#>_vis/<date>/corrected | wc -l
verify SPEC count (for SPEC UPLOAD)
ls /mnt/ppo-post-proc/<PROJECT>/fo/<dm#>_spec/<date>/corrected | wc -l
10. Redo flagged ROIs (only if needed) If a QC step fails

Only run if you marked any scans blue during VIS REV or SPEC REV. Run vroi on the same manifest — it opens only the blue-highlighted scans for re-ROI. After redo, re-run the EXTRACT-PNG QC steps to verify before uploading.

ℹ️ --df passthrough uses the existing dataframe; --t transforms the new vis ROI to the spec image automatically. Files marked red in VIS REV / SPEC REV are excluded from upload — vroi does not re-open them.
vroi — train redo
vroi /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt --df passthrough --t
Test workflow — Annotation processing. Use this tab when post-processing scans where testplan.scan_mode = t3st (note the spelling: "t3st", not "test"). Output goes to /mnt/ppo-data-services/post-processing/annotation/. Each step below maps to one spreadsheet column on the Date Page.

Recommended run order (more efficient than left-to-right on the spreadsheet): pproc (DATA PREP) → revt (VIS REV) → vis QC (VIS EXTRACT-PNG) → revt --spec (SPEC REV) → spec QC (SPEC EXTRACT-PNG) → awscp (UPLOAD — one run covers both VIS UPLOAD and SPEC UPLOAD).

Worked example below uses: Date 2026-04-25 · DM dm21040002 · Material concrete · Vis cam 2104A1813 · Spec cam 13480. Swap concrete for the actual material (e.g. green_plastic) per row.
1. Launch AWS Instance Test · Annotation

3. Pre-flight — verify file count Optional · Sanity Check

Before DATA PREP, confirm the number of raw t3st files for this material+date+dm matches the count on the spreadsheet. Catches typos and missing renames before you waste time on a long pproc run. Note the scan_mode t3st filter — using test here returns zero.

⚠️ If the count is 0, check material spelling, asterisks, and the directory. If files are still named frame* instead of t3st*, renaming hasn't completed yet — software needs more time, or escalate.
ℹ️ Run commands using full paths. Don't cd into /mnt/ppo-experimental-data or any S3 bucket — every command becomes much slower.
template

dl ls /mnt/ppo-experimental-data/<PROJECT>/fo/dm21040002_vis/2026-04-25/raw/run* --filter testplan.mat concrete --filter testplan.scan_mode t3st --bare | wc -l
4. DATA PREP (also DATA PREPer) pproc

Run pproc on the t3st raw files. The tool detects FOs (foreign objects), draws annotation boxes, generates vis/spec PNGs, and writes a post_proc_info_<#>.txt manifest under the annotation output folder. After it finishes, list the manifest filename so you can use it in the review and upload steps.

ℹ️ Spreadsheet: tick DATA PREP when this finishes; put your name in DATA PREPer. Output path: /mnt/ppo-data-services/post-processing/annotation/<date>/<vis_camera_serial>/. Add --no_split if your project doesn't split into validation/test extracts.
⚠️ Make sure you are using scan_mode t3st, not train. Train scans go through the ROI workflow (Train tab); t3st scans go through Annotation (this tab). Mixing them produces wrong output and reviewer rework.
template — pproc t3st
pproc `dl ls /mnt/ppo-experimental-data/<PROJECT>/fo/<dm#>_vis/<date>/raw/run*/frame*.h5 --filter testplan.mat <material> --filter testplan.scan_mode t3st -b`
example — concrete on 2026-04-25, dm21040002
pproc `dl ls /mnt/ppo-experimental-data/<PROJECT>/fo/dm21040002_vis/2026-04-25/raw/run*/frame*.h5 --filter testplan.mat concrete --filter testplan.scan_mode t3st -b`
find the manifest filename (post_proc_info_#.txt)
ls /mnt/ppo-data-services/post-processing/annotation/2026-04-25/2104A1813/post_proc_info_*.txt
5. VIS REV (also REVer · VIS IGNORE) revt --make_extracts

Run revt on the manifest from the DATA PREP step to review the vis annotation masks. Step through every scan and edit annotation boxes as needed.

Annotation review controls:

  • Left click empty area → add a red annotation box.
  • Left click existing box → remove it.
  • Right click a scan → mark red (un-usable, will not upload). This populates the VIS IGNORE column automatically.
  • Press q to save and exit, or ! to exit without saving.
⚠️ --make_extracts is REQUIRED. Without it your edits save to the masks but no extract files are written, so the annotations don't reach the model. If you forgot, just re-run with --make_extracts appended.
ℹ️ Spreadsheet: tick VIS REV when finished and put your name in REVer (vis side). VIS IGNORE is set automatically by your right-clicks — no separate action needed.
template — revt vis
revt /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt --make_extracts
6. VIS EXTRACT-PNG (also VIS EXTRACT-PNGer) eog / vexp

Visual QC of the vis extract PNGs. This is a separate step from VIS REV — the review step is clicking through masks; extract QC is looking at the actual output that will reach the model. Use whichever tool is faster:

  • eog *.png — quickest browse through all PNGs in the camera folder.
  • vexp <file>.h5 — opens the .h5 extract directly in vis_linescan_explorer; better when the PNG mask overlay obscures the FO.
⚠️ Reject any extract that contains: a missing FO (empty box), a cut-off FO, a tilted FO with reduced surface area, an FO inside a crevice, an O-ring inside the box, or two FOs in one box. To fix: go back to VIS REV, edit the box (or remove + re-click in the same place to force a rewrite), and re-run.
ℹ️ Spreadsheet: tick VIS EXTRACT-PNG when extracts look clean; put your name in VIS EXTRACT-PNGer. Don't tick this until you've actually opened the files — this is the gate that protects the model.
browse PNGs (vis camera)
eog /mnt/ppo-data-services/post-processing/annotation/2026-04-25/2104A1813/*.png
open one extract in vexp
vexp /mnt/ppo-data-services/post-processing/annotation/2026-04-25/2104A1813/<extract>.h5
7. SPEC REV (also REVer · SPEC IGNORE) revt --spec

Re-run revt with --spec on the same manifest. Same controls as VIS REV, but edits only affect the spec mask. Ideally no edits are needed — the coregistration from vis is usually accurate enough — but reject anything cut off or with the o-ring inside the box.

ℹ️ Spreadsheet: tick SPEC REV and put your name in REVer (spec side). Right-clicks during this step populate SPEC IGNORE automatically. Always run AFTER VIS REV, never before.
template — revt --spec
revt /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt --spec --make_extracts
8. SPEC EXTRACT-PNG (also SPEC EXTRACT-PNGer) eog / hexp

Same QC as VIS EXTRACT-PNG, but for the spec extracts. Note the path uses the spec camera serial, not the vis serial. Use hexp (the hyperspec sibling of vexp) for the .h5 files.

⚠️ Same reject criteria as VIS EXTRACT-PNG: missing FO, cut-off, tilted, in a crevice, o-ring in box, double FO. To fix, edit in SPEC REV and re-run.
ℹ️ Spreadsheet: tick SPEC EXTRACT-PNG, put your name in SPEC EXTRACT-PNGer.
browse PNGs (spec camera)
eog /mnt/ppo-data-services/post-processing/annotation/2026-04-25/13480/*.png
open one extract in hexp
hexp /mnt/ppo-data-services/post-processing/annotation/2026-04-25/13480/<extract>.h5
9. UPLOAD (VIS UPLOAD + SPEC UPLOAD; UPLOADer) awscp

Run awscp (alias of aws_copy.py; same job as the older copy3server.py) on the manifest. One run uploads BOTH vis and spec — you don't run it twice. Then verify each side independently with ls | wc -l on the corrected directories.

ℹ️ Spreadsheet: tick VIS UPLOAD after the vis count check passes, and SPEC UPLOAD after the spec count check passes. Put your name in the UPLOADer dropdowns for each side. The two checkboxes exist for independent verification, not because you upload twice.
⚠️ Use extra caution that any bad scans are not uploaded. Bad scans should have been right-clicked red during VIS REV / SPEC REV — those are excluded automatically. If you get a permissions error, the destination is mounted read-only: run mount<#>w <username> (needs rw permission) or escalate to Alan Rooks.
awscp — uploads vis + spec together
awscp /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt
verify VIS count (for VIS UPLOAD)
ls /mnt/ppo-post-proc/<PROJECT>/fo/dm21040002_vis/2026-04-25/corrected | wc -l
verify SPEC count (for SPEC UPLOAD)
ls /mnt/ppo-post-proc/<PROJECT>/fo/dm21040002_spec/2026-04-25/corrected | wc -l
10. Redo (only if needed) If a QC step fails

Most annotation fixes happen inline: re-run revt … --make_extracts at VIS REV or SPEC REV and edit the affected box (delete + re-click in the same place to force an extract rewrite). Use the vroi --spec command below only when the annotation's ROI selection itself needs to be redone for spec files.

⚠️ Confirm you are using the Test (annotation) redo, not the Train (ROI) one. The annotation redo command includes --spec; the ROI redo on the Train tab does not. Using the wrong one overwrites the wrong files.
vroi — annotation redo (spec)
vroi /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt --df passthrough --t --spec
Redo shortcut. Use this tab when you only need to re-do scans flagged blue during review and don't want to scroll through the full workflow. Train Redo and Test Redo use different commands — pick the section that matches the data you're correcting.
🔵 Train (ROI) — Redo Steps
1. Connect & activate environment Train Redo

Connect via MobaX (localhost:5902, password ppoadmin) and activate the environment with aa;caf. Make sure the calibration server is mounted: mount | grep PPO.

activate & verify mounts
aa;caf mount | grep PPO
2. Run vroi on flagged scans Train Redo

Run vroi on the same post_proc_info_<#>.txt from the original review. Only scans you marked blue in step 5 of the Train workflow will be opened.

ℹ️ --df passthrough reuses the existing dataframe. --t transforms the new vis ROI to the spec image automatically.
vroi — train redo
vroi /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt --df passthrough --t
3. Verify and upload Train Redo

Open the regenerated PNGs and confirm the new ROIs look correct, then run awscp to upload. Confirm vis & spec counts after upload.

view PNGs
cd /mnt/ppo-data-services/post-processing/roi/<date>/<camera_serial> ls eog *.png
upload
awscp /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt
🟣 Test (Annotation) — Redo Steps
1. Connect & activate environment Test Redo

Connect via MobaX and activate the environment with aa;caf.

activate environment
aa;caf
2. Re-run revt OR vroi --spec Test Redo

For most annotation fixes: just re-run revt with --make_extracts. Editing any annotation box deletes and replaces the bad extract. For ROI selection redos on spec: use the vroi --df passthrough --t --spec command.

⚠️ Confirm you are using the TEST redo command (with --spec), not the Train one. Train redo points at the roi folder and omits --spec — using it on annotation files overwrites the wrong dataset.
⚠️ If using revt to redo, --make_extracts is mandatory. Without it the extracts are not regenerated and your fix isn't propagated.
revt — re-review & rewrite extracts
revt /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt --make_extracts
vroi — annotation spec redo
vroi /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt --df passthrough --t --spec
3. Verify extracts and upload Test Redo

Open the regenerated extracts in vexp / hexp to confirm the fix looks correct, then upload with awscp.

view extract
vexp /mnt/ppo-data-services/post-processing/annotation/<date>/<camera_serial>/<file>.h5
upload
awscp /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt
