Flow Overview

1) Setup and Access

Open the launcher once, then connect to the instance over local VNC.

Downloads\ds-ec2-launcher.cmd
localhost:5902
ppoadmin
  • Open a new terminal in the VNC session for commands.
  • Terminate the instance at end of day.
  • Non-S3/non-volume local data is ephemeral and can be deleted.

2) Validate Inputs and Paths

Confirm file counts before prep and avoid running from mounted S3 directories.

dl ls /mnt/ppo-experimental-data/<project>/fo/<dm>/<spec_or_vis>/<date>/raw/run* \
  --filter testplan.mat <material_name> \
  --filter testplan.scan_mode t3st -b

dl ls /mnt/ppo-experimental-data/<project>/fo/<dm>/<spec_or_vis>/<date>/raw/run* \
  --filter testplan.mat <material_name> --bare | wc -l
  • Use full paths instead of cd into S3 buckets to avoid slowdowns.
  • For filename-only output, use --bare or -b. For metadata, use --verbose or -v.
  • Expected folders: raw input in /mnt/ppo-experimental-data/..., corrected data and extracts in /mnt/ppo-data-services/post-processing/....

3) Run Post-Processing

Generate annotation/ROI info files from VIS inputs, usually batched by material/date/DM.

python ~/ppo/tools/visual/post_processing_aws.py <raw_VIS_inputs>

pproc `dl ls /mnt/ppo-experimental-data/<project ID>/fo/<project code>/<dm#_spec/vis>/<date>/raw/run*/frame*.h5 \
  --filter testplan.mat <material_name> \
  --filter testplan.scan_mode t3st -b`

pproc `dl ls /mnt/ppo-experimental-data/<project ID>/fo/<project code>/<dm#_spec/vis>/<date>/raw/run*/frame*.h5 \
  --filter testplan.mat <material_name> \
  --filter testplan.scan_mode train -b`
  • Use --save_dir to redirect outputs.
  • Use --no_split when test/val split is not desired for extract outputs.
  • ROI generation uses train scans; annotation generation uses t3st scans.

4) Review VIS Annotations

Visually verify annotation boxes and regenerate extracts when edits are made.

revt /mnt/ppo-data-services/post-processing/annotation/post_proc_info_<#>.txt --make_extracts
  • Left-click adds/removes annotation boxes.
  • q saves + exits, ! exits without saving.
  • Saving overwrites local masks/PNGs for corrected outputs.

5) Review SPEC and ROI

SPEC and ROI checks are a separate gate; edits here must pass before upload.

# Use same info txt as VIS review step, then add --spec
python ~/ppo/tools/visual/review_tool_aws.py <same_info_txt> --spec --make_extracts

# ROI pass
revt /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt
  • For spec annotations, ensure the spec tag workflow is used consistently.
  • ROIs should isolate useful material and avoid belt/background leakage.
  • Use vexp/hexp or linescan explorer to inspect extracts deeply.

6) Quality Checklist (From Reminders)

Annotation Mistakes

  • Missing FO
  • Cut-off FO
  • FO too tilted (surface appears too small)
  • FO in crevice / wrong target
  • O-ring inside extract region
  • Double FO in one extract box

ROI Mistakes

  • Belt included in ROI
  • Spec tag flow not followed
  • ROI too small for density section
  • ROI should include enough material signal

Acceptable: FO may be off-center if not cut off. Boat/density ROI styles are valid when material coverage is sufficient.

7) Redo Branch and Manual Edits

Use the redo queue for files that need rework, and escalate to manual tools only when needed.

# Mark redo in review UI, then run manual ROI utility on the same post_proc txt
python ~/ppo/tools/visual/polygon_select_ROI_aws.py \
  /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt --df passthrough --t

vroi /mnt/ppo-data-services/post-processing/roi/post_proc_info_<#>.txt --df passthrough --t
  • Blue highlight: redo candidate.
  • Red highlight/right-click: unusable, do not upload.
  • Re-run review tool with --make_extracts after fixes.

8) Upload and Closeout

Upload corrected files only after both VIS and SPEC checks pass.

python ~/ppo/tools/data_utils/aws_copy.py <post_proc_txt>
awscp <post_proc_txt>
  • Run upload from the correct .../corrected directory context.
  • Verify both VIS and SPEC files were moved.
  • Then clean temporary local files/folders to free space.

9) Spreadsheet Operations (Coordination Layer)

Use the Date Page to allocate work and track completion for PP, Review, and Upload.

  • VIS/SPEC PP: checkbox for post-processing completion.
  • VIS/SPEC REV: checkbox for review completion.
  • VIS/SPEC UPLOAD: checkbox for upload completion.
  • PPer/REVer/UPLOADer: assign the current owner by dropdown.

If a scan cannot be processed, note it in comments and keep status explicit.

10) Frequent Errors and First Fix

Display/Review Tool (TMUX)

If review tool cannot open display/new window, detach tmux with Ctrl+B then D, kill/recreate tmux, retry.

No module named cv2

Run environment initialization before aliases: aa;caf.

No such file or directory

ls run*/[t3st/train]*material*.h5 | wc -l then verify typos/path or prior moved files.

Calibration path missing

mount | grep PPO, then mount#, password ppoadmin.

Upload permission error

Confirm mount mode (rw vs ro) with mount | grep PPO. If needed: mount#w [username].

11) Advanced Recovery: VIS h5 exists, SPEC missing

  1. Move VIS files to temp: mv *files* /mnt/data1/u/annotation/[temp folder name].
  2. Re-run prep on server to regenerate VIS/SPEC h5 + fresh txt.
  3. Delete regenerated local placeholders using rm, then move original files back.
  4. Run review pass with --make_extracts and avoid --spec first.
  5. Touch each vis annotation box in-place (remove+replace same spot) to force re-write.
  6. Re-review spec with review_tool.py --spec --make_extracts.
  7. Upload regenerated validated files and clean temp folders.
